# チェックアウト

作業を終えるときの締めです。

> **この作業は `main` へのマージまで完了させてください。**
> セッションのコンテナは終了後に破棄されます。引継ぎが作業ブランチに残ったままだと、
> 次のセッションは `main` を新規クローンするため、**更新した引継ぎは失われます**。
> 「PR を出した」で止めないでください。マージされて初めて引き継がれます。

## 手順

### 1. 引継ぎを更新する

`docs/handoff.md` の4節を、次のセッションが**これだけ読めば再開できる**水準に書き換えます。
`<!-- session-end-stamp -->` 以降は自動記録なので触りません。

- **いま何をしているか** — 目的と到達点。完了していれば「完了済み。次の作業は未着手」
- **完了したこと** — 変更したファイル、PR の番号とリンク、通した検証。実際に確認した事実だけ
- **次にやること** — 具体的な次の一手。判断待ちなら、誰の何の判断を待っているか
- **注意点** — 踏んだ落とし穴、未解決の問題、**試して駄目だった方法**

確度の低い記述には `[曖昧]` を付けます。

### 2. 検証を通す

```bash
pnpm run check
pnpm run build
```

失敗したまま締めないでください。直せない場合は、その事実と原因を引継ぎの「注意点」に書きます。

### 3. コミットして push する

`main` への直接 push は Ruleset で禁止されています。作業ブランチへ push してください。

### 4. PR を出してマージする

- **作業の PR がすでにある場合** — 引継ぎの更新をその PR に含めてマージします
- **作業の PR が無い場合**（調査だけで終わった等） — 引継ぎ単体で PR を出してマージします

CI が緑になるのを待ち、ドラフトなら解除してからマージします。

### 5. main に載ったことを確認する

```bash
git fetch origin main
git show origin/main:docs/handoff.md | head -30
```

**更新内容が `origin/main` 側に見えることを目視で確認してください。** ここまでやって完了です。

## 報告の形式

```
引継ぎ: 更新済み / main にマージ済み（<コミットSHA>）
検証: check 通過 / build 通過
残件: <次のセッションが引き継ぐこと。無ければ「なし」>
```

マージできなかった場合は、**何が阻んでいるか**を明記してください。CI が赤い、コンフリクト、
必須チェックが未実行など、原因を特定して報告します。黙って終わらせないこと。
