# 引継ぎの更新

`docs/handoff.md` を、**次のセッションがこれだけ読めば再開できる**水準に更新します。

## 手順

1. `docs/handoff.md` を読み、現状との差分を把握する
2. `git status` と `git log --oneline -10` で、このセッションの変更を確認する
3. 以下の4節を書き換える（`<!-- session-end-stamp -->` 以降は自動記録なので触らない）
4. `docs/handoff.md` をコミットする。**コミットしないと次のセッションに残らない**

## 書く内容

**いま何をしているか**
目的と、どこまで進んだか。作業が完了しているなら「完了済み。次の作業は未着手」と書く。

**完了したこと**
変更したファイル、出した PR の番号とリンク、通した検証。「動くはず」ではなく、実際に確認した事実だけを書く。

**次にやること**
具体的な次の一手。判断待ちがあるなら、誰の何の判断を待っているかを書く。

**注意点**
踏んだ落とし穴、未解決の問題、**試して駄目だった方法**。同じ失敗を繰り返させないため、駄目だった方法は特に価値がある。

## 書かないこと

- 経緯や検討の過程。結論と次の一手だけでよい
- コードを読めば分かること。ファイルの一覧や関数の説明は不要
- 一時的な情報。次のセッションで無意味になるものは書かない

確度の低い記述には `[曖昧]` を付けてください。
