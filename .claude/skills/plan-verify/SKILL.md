# 全体照合

**「verified」を信用せず、実物だけを見ます。**

## なぜ必要か

項目ごとの完了判定は、その回に作った1項目しか見ません。だから次のことが
構造的に検出できません。

```text
T003 を verified にした
  ↓
後のセッションで T007 の作業をした
  ↓
その変更で T003 が壊れた
  ↓
T003 はもう verified なので、誰も見に行かない → 誰も気づかない
```

**全体照合はこれを見つけるためだけにあります。**

## いつ走らせるか

`pnpm run plan:state` が `GLOBAL_VERIFY_REQUIRED` を返したときです。自分で判断して
呼ぶ必要はありません（`verified` が前回から10増えたとき、および全項目が片付いたときに
自動でこの工程になります）。

## 手順

### 1. 対象を絞る

```bash
pnpm run test
```

`verifyBy` が `ci` の項目は、CI が毎コミット見ています。**手でなぞるのは
`verifyBy` が `agent` / `human` の項目だけ**です。100項目あっても実際になぞるのは数件になります。

### 2. 照合役を立てる

**このセッション自身で照合しないでください。** まっさらなサブエージェントに委譲します。
渡す指示は次のとおりです。

```text
docs/plan.json の verifyBy が agent または human の項目について、
title / deliverable / verify だけを読んでください。

見てはいけないもの:
  - status 欄（「verified」と書いてあっても信用しない）
  - git のコミット履歴
  - 誰かの「できました」という報告

実際のファイルを開き、verify の手順を自分でなぞってください
（human の項目は、実物を見るしかない箇所だけ「確認できない」と明記してください）。
各項目について、次の4分類で報告してください。

  できている / 途中まで / 書いてあることと違う動きをする / 頼んでいないものが増えている

判定の根拠として、実行したコマンドと返ってきた内容そのものを付けてください。
verify に書かれていないことは指摘しないでください（コードの書き方、設計、命名、
将来の拡張性はすべて対象外）。

ファイルは1つも変更しないでください。報告だけしてください。
```

### 3. 報告を受け取る

```text
T001  できている
T002  できている
T003  ★ 書いてあることと違う動きをする
      確かめ方: 画面幅を375pxまで狭める → 文字がはみ出していないこと
      実際    : 幅375pxで住所が右にはみ出す
      根拠    : style.css の .address に white-space: nowrap がある
```

### 4. 壊れが見つかったときの記録

**`verified` を `todo` に戻さないでください。** 末尾に新しい番号で追記します。

```json
{
  "id": "T101",
  "title": "T003 の住所がスマホ幅ではみ出す件を直す",
  "deliverable": "幅375pxで会社概要の住所が画面内に収まる",
  "verify": ["about.html を開く", "幅を375pxにする", "住所がはみ出していないことを確認する"],
  "dependsOn": ["T003"],
  "files": ["style.css"],
  "verifyBy": "ci",
  "verifyCommand": "pnpm run test -- about",
  "status": "todo",
  "origin": "added",
  "note": "全体照合(2026-09-03)で発見。T007 の変更が原因"
}
```

**理由**：`verified` を `todo` に戻すと、同じ項目が2回終わったことになり履歴が壊れます。
追記なら「T003 は一度完成し、T101 で直した」という事実がそのまま残ります。番号は不変です。

### 5. カバレッジを出して締める

照合を終えたら、対象にした件数・「できている」件数・見つかった壊れの件数を報告し、
`docs/checkpoints.json` の `globalVerifiedCount` を、いまの「済」件数
（`pnpm run plan:progress` の数字）に更新します。

**`unverified > 0`（照合していない項目が残っている）なら「全体照合完了」と報告しないでください。**
対象を絞りすぎていないか、もう一度確認します。

## やらないこと

- **このスキル自身はファイルを変更しません。** 変更するのは、報告を受けた後に追記する
  `docs/plan.json` の1箇所と、`docs/checkpoints.json` の更新だけです
- 照合役に「改善点を探せ」と指示しない。`verify` の手順が通るかどうかだけを見させる
- 壊れを見つけたその場で直さない。追記して、通常のセッションで1項目として扱う
