# プロジェクトの初期化

**雛形をコピーした直後に、一度だけ実行します。**

## なぜ必要か

この雛形をコピーしただけの状態では、`docs/handoff.md` に**雛形自身の開発履歴**が残っています。
`AGENTS.md` は毎セッション `docs/handoff.md` を読み込むため、放置すると新しいセッションは
「このプロジェクトは雛形の開発である」と認識します。そこから会話が始まってしまいます。

技術構成も同じです。`docs/stack.md` には雛形の既定（Node / TypeScript）が入っています。
Python のプロジェクトなら毎セッション矛盾した指示を読むことになります。

## 実行済みかどうかの見分け方

`AGENTS.md` の冒頭に次の一文が**残っていれば未初期化**です。

```
このリポジトリを雛形として使い始めたら、この行を実際のプロジェクトの目的に書き換えてください。
```

すでに消えているなら初期化済みです。**実行せずにその旨を報告して終わってください。**

## 手順

### 1. 目的を聞く

**これがコピー後の最初のやり取りです。** 他の作業より先に聞いてください。

```
このリポジトリの目的は何ですか？（1〜2行で）

  「何ができたら完成か」が分かる書き方にしてください。

  ✗ 顧客管理システムを作る
  ✓ 訪問営業の顧客管理を、既存の顧客3社で毎日回せる状態にする
```

答えを `AGENTS.md` の `**目的**:` の行に書き、**「雛形として使い始めたら書き換えてください」の
一文を削除します。** この一文の有無が、初期化済みかどうかの判定に使われています。

### 2. 技術構成を聞く

```
技術構成はどうしますか？

  [ 1 ] Node + TypeScript（この雛形の既定。そのまま使う）
  [ 2 ] Python
  [ 3 ] 既存の OSS に乗せる（fork / clone する）
  [ 4 ] 上記以外
  [ 5 ] まだ決めない
```

- **1** — `docs/stack.md` はそのまま。何もしない
- **2** — `docs/stack.examples/python.md` を `docs/stack.md` へコピーし、実際に使うものへ直す
- **3** — `docs/stack.examples/existing-oss.md` を `docs/stack.md` へコピーする。
  **乗せる先の URL と、本家の更新をどう取り込むかを必ず聞いてください**
- **4** — `docs/stack.md` を白紙から書く。見本の見出し構成（前提環境 / コマンド /
  コーディング規約 / この構成での落とし穴）は保つ
- **5** — `docs/stack.md` の中身を「未定」にし、決まった時点で書くことを `docs/handoff.md`
  の「次にやること」に残す

**構成を変えたら、雛形の残骸を消してください。** Python にしたのに `package.json` と
`src/*.ts` が残っている、といった状態は混乱の元です。何を消すかはユーザーに確認します。

**`scripts/check-plan.mjs` だけは、どの構成でも残します。** 依存関係ゼロの素の JavaScript で、
全体計画の番号の不変性を守る唯一の機械的な歯止めです。Node さえあれば動きます。

### 3. 引継ぎ文を初期化する

```bash
cp docs/handoff.template.md docs/handoff.md
```

**雛形自身の開発履歴はここで消えます。** 消えて困る内容ではありません（雛形の
リポジトリに git 履歴として残っています）。

### 4. 台帳を確認する

`docs/failure-action-log.md` と `docs/neglected-log.md` に記録が残っていたら消します。
**前のプロジェクトの失敗記録を引き継ぐと、無関係な記録を読んで判断を誤ります。**

### 5. 検証を通す

```bash
node scripts/check-plan.mjs   # 計画がまだ無ければ「読めませんでした」で正常
```

`docs/stack.md` に書いた検証コマンドも実行し、通ることを確認します。

### 6. 報告して次へつなぐ

```
初期化しました。

  目的      : <書いた目的>
  技術構成  : <選んだもの>
  引継ぎ文  : 初期化済み
  消したもの: <雛形の残骸。無ければ「なし」>

次は /plan-init で全体計画を作ります。実行しますか？
```

## やらないこと

- **`docs/decisions.md` は消さない。** 雛形自身の設計記録だが、**なぜそのルールがあるか**の
  説明であり、コピー先でも有用です。冒頭に「これは雛形自身の設計記録」と1行足すに留めます
- **`docs/test-policy.md` は消さない。** 言語に依存しない品質の方針です
- **`.claude/` 配下は消さない。** スキルとサブエージェントが運用の本体です
- 目的を聞かずに推測で書かない。**リポジトリ名やコードから推測した目的を、確認なしに
  `AGENTS.md` へ書き込まないこと**
