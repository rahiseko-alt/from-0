# 問題の仕分け

**見つけた問題を、いま直すか・記録して進むかだけを決めます。** 製品全体の良し悪しは見ません
（それは `/release-review` の仕事です）。

正本は `docs/test-policy.md`。この skill はその「Issue Triage」側の手順を呼び出すだけです。

## 手順

1. **`docs/test-policy.md` の Gate 表（001〜100）を上から見て、この問題が当たる番号を1つ決める**
   - 番号を付けられない問題は、不具合ではなく「気になること」です。**扱いません**
   - 変更範囲に関係するカテゴリだけ見ればよい。100項目を毎回全部出力しない

2. **番号で処理が決まる**

   | 番号     | どうするか                                                                 |
   | -------- | -------------------------------------------------------------------------- |
   | 001〜080 | **いま直す。** ここに NO が1件でもあれば公開できないため、後回しにできない |
   | 081〜100 | **記録して進む。** `pnpm run gate:record` で台帳に1行                      |

   ```bash
   pnpm run gate:record -- 087 BACKLOG "scripts/plan-cli.mjs" "毎回ビルドが走る"
   ```

3. **001〜080 でも、いまのセッションの範囲外なら項目として積む**

   ```bash
   pnpm run plan:next-id   # 次に振る番号
   ```

   `docs/plan.json` の末尾に追記し、**このセッションでは直しません**。例外は
   「いま作業中の項目の `verify` 自体が破れた」場合だけ（それは今回の作業そのものです）。

## しょうもない問題に追われないための規則

- **再現手順の無い指摘は無効。** 「〜の可能性がある」は扱わない
- **改善提案・命名・拡張性は対象外。** 書いてきたら読まずに捨てる
- **同じ Gate・同じ箇所で2回目**なら `docs/failure-action-log.md` へ。**3回目以降は無視**
- 下位の番号の問題を先回りして直さない（`docs/test-policy.md`「Scope Rule」）

## 報告

```text
FAILED_GATE: 023
原因:
証拠:
修正対象:
修正しない範囲:
```

問題が 081 以降で記録だけした場合は、記録した旨の1行で足ります。
