# 技術構成（見本: 既存 OSS に乗せる場合）

**これは見本です。** 使うときは `docs/stack.md` へコピーし、実際の構成に合わせて直してください。

既存の OSS を fork／clone して、その上に自分のプロジェクトを作る場合の書き方です。

---

## 大前提：構成は「乗せる先」に合わせる

**この雛形の構成を持ち込まないでください。** 乗せる先が npm を使っているなら npm を、
yarn なら yarn を使います。雛形の都合で pnpm に変える、TypeScript の設定を上書きする、
Prettier の設定を差し替える——**どれも本家の更新を取り込めなくする原因になります。**

雛形から持ち込むのは**運用の仕組みだけ**です。

| 持ち込む                                              | 持ち込まない             |
| ----------------------------------------------------- | ------------------------ |
| `AGENTS.md` / `CLAUDE.md`                             | パッケージマネージャ     |
| `docs/handoff.md` `decisions.md` `plan.json` と各台帳 | リンタ・フォーマッタ設定 |
| `.claude/`（スキル・サブエージェント・フック）        | ビルド設定・tsconfig     |
| `scripts/check-plan.mjs`                              | ディレクトリ構成         |

## この構成での落とし穴

- **本家のファイルを直接書き換えるほど、更新を取り込みにくくなる。** 可能なら
  「追加」で済ませ、「改変」は最小限にする。改変した箇所は `docs/decisions.md` に理由を残す
- **本家の CI 設定を消さない。** `check` ジョブを足す形にする
- **`node scripts/check-plan.mjs` は Node が要る**（全体計画を使う場合）
