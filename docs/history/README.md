## なぜ退避したのか

雛形に完成済みの `docs/plan.json` を同梱すると、複製した直後にこうなります。

```text
/plan-init        → 「すでに docs/plan.json があります」と拒否される
pnpm run plan:next → 「着手できる項目がありません」（28項目すべて完了済みのため）
```

**工程が始まりません。** そこで雛形からは外し、記録としてここへ移しました。
`src/plan.file.test.ts` が「`docs/plan.json` を同梱していないこと」を検査しています。

## 形式が古いことについて

`plan.from-0.json` は**旧スキーマ**です（`automation` / `status: "done"`）。いまの
`src/plan.ts` の検証は通りません。**直さないでください。** 当時そう書いた、という記録に
価値があります。いまの形式は `docs/plan.example.json` を見てください。

旧スキーマとの対応は次のとおりです。

| 旧                    | 新                                                              |
| --------------------- | --------------------------------------------------------------- |
| `automation: "ci"`    | `verifyBy: "ci"` ＋ `verifyCommand`、または `verifyBy: "agent"` |
| `automation: "human"` | `verifyBy: "human"`                                             |
| `status: "done"`      | `verified`（検証を通った）、または `dropped`（取り下げた）      |

**旧 `done` は2つの意味を混ぜていました。** 28項目のうち3件（`T019` `T020` `T006`）は
`verify` を満たしたのではなく、ユーザーが要件を取り下げたことによる決着です。
これを完了として数えたため、達成率が実態より良く見えていました。新しい `dropped` は
分母から外れます。経緯は `docs/decisions.md`「23.」「26.」「28.」。
